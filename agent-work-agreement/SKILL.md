# Agent 工作约定

本文档是用户与本仓库 AI 协作方的正式约定。它定义的是流程，不是技术实现；目标是让每一步修改都可追溯：文档记录意图，代码实现意图，提交固化结果。

**总门禁**：任何修改动作（写文件、改代码、改配置、更新版本号）在执行前必须得到用户的明确确认。用户消息中的直接指令本身就是确认，无需重复追问；但超出指令范围的连带修改必须先提出、获准后再动。

## 开发流程

1. **文档先行**：开始新设计前，先根据用户提出的需求、架构、模块设计编写完整的设计文档，放入 `doc/` 对应位置。内容包含：设计思路、代码示例、类图、时序示例等图示，以及演进路线（列出待办事项）。文档是开发流程的核心，代码是文档的实现。
2. **评估先于动手**：收到工作内容与设计需求后，按以下顺序推进：
   - 对照当前实现与既有文档规划做评估，给出客观评估结果（可行性、技术方向、更优实现），不盲目支持用户；
   - 确认工作方向后，先更新文档：拆分工作、罗列待办事项；
   - 交用户确认；确认通过后才开始修改代码；
   - 按拆分后的步骤逐步执行，多次提交，不要试图一步完成所有修改。
3. **文档与代码同步**：每次代码修改都必须保证文档与代码状态一致。
4. **完成核对**：修改完成后与文档逐项对比，确认需求全部实现；随后更新文档，把已完成的待办事项标记为完成。
5. **只评估不实现**：用户要求评估新功能但不要求马上实现时，完成评估并得到确认后，把该功能写入相关文档的演进路线，作为未来待办事项，不写代码。

## 文档整理

如果发现文档中的已完成待办事项过多，可提醒用户开始整体文档的工作，但禁止自行对文档做日常工作以外的整理。

## 版本号与 CHANGELOG

- 需要更新版本号的修改，必须同步更新 `CHANGELOG.md` 与 `CHANGELOG.en.md`；不更新版本号的修改不动 CHANGELOG。
- 版本号格式为三段式 `x.y.z`（`package.json` 的 `version` 字段，不含 `v` 前缀）。用户未明确说明时默认 patch 位 +1（如 1.3.2 → 1.3.3）；用户有明确要求时按要求执行。
- 版本号的更新发生在提交准备阶段，不发生在功能修改阶段。

## 提交准备

- 用户通知"准备提交"时，才执行收尾：更新版本号，并生成一份英文版 commit message（每次的具体格式以用户约定为准）。
- **commit message 单行不超过 100 字节**（UTF-8 字节数，汉字每字 3 字节）：标题行与正文行同等约束。
- **commit message 全文尽量不超过 500 个英文字符**：说清"改了什么、为什么、验证了什么"即可，展开细节交由正文文体克制与 roadmap/手册承载。
- **提交流程固定为"临时文件 → 检查 → 提交"**：先将 commit message 写入临时文件（如 `/tmp/commit-msg.txt`），用 `awk 'length($0) > 100' /tmp/commit-msg.txt` 逐行自检（有输出即重写），检查通过后以 `git commit -F /tmp/commit-msg.txt` 提交——**不要用多个 `-m` 拼接**（长段落正是从那里产生的）。已因漏检发生过多起，此流程不可省略。
- **提交必须由用户明确确认，禁止自行决定提交**：只有用户针对本次提交给出明确许可（例如"可以提交"、"提交吧"、"确认"）时，才可执行 `git commit`；提出的确认请求必须被用户真正回应，**不得以"用户的沉默、后续的新指令、或此前对方案/文档的确认"推断提交已获批准**——对设计方案的确认不等于对提交的确认。用户可随时要求只提交其中一部分，未获许可的仓库一律保持未提交状态。
- 提交动作固定为 `git add` + `git commit`：按仓库分别提交（`build`/`bsp`/`thirdparty`/`system` 各自独立），只暂存本轮改动的文件、不夹带无关改动，提交后回报各仓库的提交号与标题。

## 禁用的 git 命令

以下命令一律禁止执行：

```
git branch / checkout / push / pull / rebase / reset / cherry-pick / remote
```

分支、历史与远程是用户的领地：创建、切换、改写、发布提交的决定权完全在用户手中。`git commit` 是唯一例外——**仅在用户对本次提交给出明确确认后执行，禁止自行决定提交**（见"提交准备"：对方案的确认不等于对提交的确认）； `--amend` 仅在用户**明确要求**改写某笔提交时使用（如修正 message），其余改写历史的操作（`rebase` 等）与 `--no-verify` 一律禁止。允许的 git 操作为只读命令（`status` / `diff` / `log` / `show` 等）、暂存（`add`）与获明确确认后的 `commit`。
